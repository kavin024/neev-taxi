# Operations

## Configuration

Settings are environment variables prefixed `NEEV_`, loaded from `backend/.env` and
`backend/.env.local` (development only; use real environment variables elsewhere).
Start from `backend/.env.example`. Money is in paise; durations are seconds unless a
name says otherwise.

### Critical settings

| Variable | Default | Notes |
| --- | --- | --- |
| `NEEV_APP_ENV` | `development` | `production` activates the fail-closed adapter guard |
| `NEEV_DATABASE_URL` | local embedded PG | Use `postgresql+psycopg://user:pass@host/db` in production |
| `NEEV_SECRET_KEY` | random per boot | **Must** be ≥ 32 chars and stable, or tokens/PINs break on restart |
| `NEEV_PUBLIC_BASE_URL` | `http://localhost:8000` | Used in share links and document URLs |
| `NEEV_CORS_ORIGINS` | localhost dev ports | Comma-separated exact origins |
| `NEEV_PAYMENT_PROVIDER` | `sandbox` | `razorpay` requires key id/secret/webhook secret |
| `NEEV_SMS_PROVIDER` | `outbox` | `twilio` requires SID/token/from number |
| `NEEV_MAP_PROVIDER` | `demo` | `osm` uses Nominatim + OSRM; set a real user agent |
| `NEEV_UPLOAD_DIR` | `var/uploads` | Must be writable and backed up |
| `NEEV_RUN_BACKGROUND_JOBS` | `true` | Disable when running multiple workers and an external scheduler |

Development-only switches (`NEEV_DEV_OTP_ENABLED`, `NEEV_DEV_OTP_FIXED_CODE`,
`NEEV_DEV_OTP_RETURN_CODE`, `NEEV_DEV_AUTO_APPROVE_CAPTAINS`,
`NEEV_DEV_ALLOW_GPS_SIMULATION`) and the sandbox/outbox providers cause startup to
raise `Unsafe production configuration` when `NEEV_APP_ENV=production`.

### Tuning

| Variable | Default | Meaning |
| --- | --- | --- |
| `NEEV_DISPATCH_RADIUS_KM` | 5 | Candidate search radius |
| `NEEV_SEARCH_TIMEOUT_SECONDS` | 90 | Ride search window |
| `NEEV_OFFER_TIMEOUT_SECONDS` | 45 | Per-captain offer window |
| `NEEV_CAPTAIN_STALE_LOCATION_SECONDS` | 180 | Ignore older captain heartbeats |
| `NEEV_MAX_OFFERS_PER_REQUEST` | 8 | Fan-out limit |
| `NEEV_LOCATION_MAX_AGE_SECONDS` | 180 | Reject stale client GPS pings |
| `NEEV_ROUTE_DEVIATION_THRESHOLD_M` | 500 | Deviation flag threshold |
| `NEEV_PIN_TTL_MINUTES` | 30 | Trip PIN validity from assignment |
| `NEEV_SOS_COOLDOWN_MINUTES` | 30 | Per-user SOS cooldown |
| `NEEV_SHARE_LINK_TTL_MINUTES` | 240 | Default share-link lifetime |
| `NEEV_DOCUMENT_URL_TTL_SECONDS` | 300 | Signed document URL lifetime |

## Local development

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt
.venv/bin/python scripts/dev_backend.py            # migrate + seed + serve :8000
```

Useful variants:

```bash
.venv/bin/python scripts/dev_backend.py --reload --no-seed
.venv/bin/python scripts/dev_db.py                 # database only
.venv/bin/python scripts/seed_demo.py --reset-demo # idempotent, dev/test only
```

The embedded server keeps data in `/tmp/opencode/pgdata` by default; override with
`NEEV_PG_DATA`. It is a development convenience, never a production database.

Admin console:

```bash
cd apps/admin_web
npm ci
npm run dev        # :5173, proxies /api and /health to :8000
npm run build      # static bundle in dist/
npm run preview    # :4173
```

To point a built console at another API origin set `VITE_API_BASE_URL` at build
time (leave empty to use the same origin through a reverse proxy).

Flutter clients read `API_BASE_URL` at build time:

```bash
flutter run -d chrome --dart-define=API_BASE_URL=https://api.example.com
flutter build web --release --dart-define=API_BASE_URL=https://api.example.com
```

## Migrations

```bash
cd backend
../.venv/bin/alembic upgrade head
../.venv/bin/alembic revision --autogenerate -m "describe change"
../.venv/bin/alembic check          # confirm metadata and migrations agree
```

Run migrations as a separate deploy step before starting new API processes. The
suite includes `tests/test_migrations.py`, which upgrades from an empty database.
Review autogenerated revisions: they must not drop columns or constraints
destructively without a backfill plan.

## Containers

`infra/docker-compose.yml` brings up PostgreSQL, the API (migrating on start) and the
admin console behind nginx.

```bash
cd infra
cp .env.example .env               # set secrets; do not commit it
docker compose up --build
# console http://localhost:8080, API http://localhost:8080/api/v1, health /health
```

The compose file is a **local demonstration** stack: it runs the API with
`NEEV_APP_ENV=development` so the sandbox providers work. Do not expose it to the
internet. For a real deployment, build the same images, run with
`NEEV_APP_ENV=production`, supply managed PostgreSQL, object storage and real
providers, terminate TLS at the edge, and run at least two API replicas.

### Manual production topology

1. Managed PostgreSQL 16 with automated backups and PITR.
2. Two or more API containers behind a load balancer; WSS upgrades enabled.
3. Static admin bundle on a CDN, `/api` and `/health` proxied to the API.
4. Shared object storage for documents, mounted or synced at `NEEV_UPLOAD_DIR`.
5. Redis for rate limiting and WebSocket fan-out before scaling past one worker
   (the in-repo limiter and socket registry are process-local; `NEEV_ENABLE_REDIS`
   is reserved and currently unused).
6. Scheduled job running the expiry sweep if background jobs are disabled.

## Health and observability

- `GET /health` reports API, database, environment and active providers. It returns
  `200` with `"status":"degraded"` when the database is unreachable; alert on the
  status field, not only the HTTP code.
- Every response carries `X-Request-ID`; logs include request id, method, path,
  status, latency and client IP.
- Counters worth alerting on: 5xx rate, `/health` degraded, `rides.expired` spikes
  (supply shortage), `safety.sos` events, payment webhook failures, SMS failures.
- Audit log (`/api/v1/admin/audit-logs`) is the record of operator actions.

## Runbook

**Ride stuck in `searching`.** The expiry job normally closes it at 90 s. Check
`NEEV_RUN_BACKGROUND_JOBS`; if disabled, ensure the external sweep is running. An
operator can cancel the request with a support note.

**No captains receive offers.** Verify captains are approved, online, have a fresh
location (< 180 s), an active vehicle in the requested category, are within the
dispatch radius, and are not on an active trip. Check service-area coverage.

**Two captains claim one ride.** Expected loser receives `409 ride_unavailable`; the
conditional update guarantees one winner. Look for `IntegrityError` on assignment in
logs if this repeats.

**Passenger cannot start the trip.** The captain must be in `arrived`; the PIN is
bound to the trip and expires after `NEEV_PIN_TTL_MINUTES`. Failed attempts are
limited; issue a new trip only through a cancellation/rebook, never by sharing the
PIN over chat.

**Payment succeeded but ride shows unpaid.** Check the payment provider reference and
webhook delivery. Sandbox confirmations are explicit; Razorpay relies on the signed
webhook. Reconcile against `payment_transactions` and `ledger_entries` before manual
settlement.

**Refund or payout pending.** They require an admin decision. Approving posts the
reversing ledger entries; rejecting requires a note. Never edit ledger rows by hand.

**SOS raised.** The incident appears in the admin safety queue and notifies the
participants. This build does **not** call emergency services. Follow your
organisation's safety protocol; record the resolution note.

**Document upload failing.** Check `NEEV_UPLOAD_DIR` permissions and
`NEEV_MAX_UPLOAD_BYTES` (10 MB default). Only images are accepted; MIME type is
validated server-side, not trusted from the client.

**Admin locked out.** Create/reset an admin through a database migration or an
existing super admin. Passwords are Argon2id and cannot be recovered.

## Backup and retention

Back up PostgreSQL (daily full + PITR) and `NEEV_UPLOAD_DIR` together; a document
row without its file is unusable. Retain audit logs and payment records per local
law. The privacy policy you publish must match actual retention: OTP challenges,
refresh tokens and stale location breadcrumbs should be purged on a schedule. No
purge job ships with this MVP — add one before launch.

## Release checklist

- [ ] `NEEV_APP_ENV=production`, `NEEV_SECRET_KEY` ≥ 32 chars and stored in a secret manager
- [ ] Real payment and SMS providers configured and webhook signatures verified
- [ ] `alembic upgrade head` completed; `alembic check` clean
- [ ] Document storage writable, backed up and access-controlled
- [ ] TLS, HSTS, trusted proxy headers and exact CORS origins configured
- [ ] Shared rate limiting and WebSocket fan-out (Redis) if more than one worker
- [ ] Backups, log retention, alerting and on-call ownership agreed
- [ ] Safety, cancellation, refund and privacy policies reviewed by the business
- [ ] Demo seed and all development adapters disabled
